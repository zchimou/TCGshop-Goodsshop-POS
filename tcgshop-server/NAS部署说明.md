# TCGshop POS NAS 同步服务（v1.4.0-test）

这是独立的 POS 服务。请新建 Docker 项目，保留原示例经营账项目、5688 端口和 ledger.json。新服务默认使用 5689 端口，挂载 ./data，店铺保存在 data/shop.json。部署包没有预设管理员或同步密钥。

## 飞牛 fnOS 部署

1. 将部署 ZIP 解压到 NAS 的独立目录，例如 /docker/tcgshop-pos-sync。目录内应直接包含 Dockerfile、docker-compose.yml、server.js、sync-core.js，不要覆盖原经营账目录。
2. 在该目录新建 .env 文件，内容为 SYNC_TOKEN=你自行生成的随机长密钥。建议至少 32 位字母数字；不能留空。可以复制 .env.example 后重命名并填写。密钥是服务访问凭证，与管理员登录密码不同。
3. 在飞牛 Docker → 项目/Compose 中从此目录创建项目，构建并启动。使用终端时可在该目录运行 docker compose up -d --build。Compose 挂载 ./data:/data；升级时保留 data 和 .env。
4. 如 NAS 仍使用原说明中的 192.0.2.10，POS 服务地址为 http://192.0.2.10:5689。NAS IP 不同时请换为当前地址；5689 被占用时修改 Compose 左侧端口，并在 App 中填写对应端口。
5. 在已有正式 POS 账本的主设备覆盖安装 v1.3.0-test。管理员登录 → 数据与设置 → NAS 存储与同步，填写上一步地址与同一密钥，点击测试连接，再立即同步。新 NAS 尚无店铺时会上传本机完整店铺。已有店铺时先比较数据，再明确选择保留哪一份。
6. 勾选保存后自动同步，以及登录、返回前台与在线期间自动检查，点击保存设置。普通保存后约 1 秒触发；有操作弹窗时等待关闭后再同步，在线前台每 30 秒检查一次。
7. 第二台设备安装新版，在登录页选择从 NAS 连接已有店铺，填写地址和密钥，预览并输入「载入NAS」确认。载入后使用主设备已有的管理员或店员账号登录，不要再创建另一套管理员后直接上传。

安装应用不能代替部署 Docker 服务。当前文件已在电脑上生成和验证，未直接部署到你的 NAS。

## 保存范围与断网

NAS 保存商品、商品封面、分类/成本选项、SKU 序号、库存、销售小票、独立退款记录、出入库流水、经营支出、账号和权限。密码只保存 PBKDF2 盐值与派生结果，没有明文密码。购物车、待结账优惠、相机偏好、NAS 密钥和登录会话留在设备上。

本机仍保存离线副本。断网、服务不可达或密钥错误时不清空账本；重连或返回前台后按开关继续同步。应用关闭后不承诺后台上传。账号停用和密码修改在其他设备成功同步后生效，离线设备仍使用上次同步的账号资料。账号管理限制在 App 内执行；同步密钥可读写完整店铺，须由管理员保管并配置授权设备。

同一店铺仍建议切换设备前确认显示同步成功。本版使用版本校验的整店同步，不是支持多个收银台同时成交的中心交易服务器。离线多机销售可能形成库存差异，不能保证跨设备实时防超卖。

## 双端修改与冲突

只改了一端时自动上传或下载。两端都修改并且内容不同，或第一次连接已有其他店铺时，自动同步暂停；不会把库存数相加、重编 SKU、覆盖订单或重复退款。

同一店铺双端均有修改时，客户端会先保存本机与 NAS 的完整差异快照，再按销售、退款、盘库、支出和出入库流水的唯一记录编号合并。双方新增的记录都会保留；库存变化按未同步的出入库流水增量应用一次，避免旧设备覆盖另一台设备的销售记录。相同编号的记录以 NAS 版本为准，商品资料和相同编号的商品操作也遵循此规则。合并成功后两台设备重新得到同一份账本。

首次连接到已有的陌生店铺、同步身份不一致或 NAS 数据目录为空时仍停止自动覆盖，必须由管理员核对后处理。所有平板须升级修复版；旧客户端仍可能执行旧的本机覆盖策略。已被旧客户端覆盖的记录需要从 NAS 历史备份或尚保留记录的设备恢复，升级不会自动找回。

同步前保留最新本机快照，可在设置中导出同步前快照。普通账本 JSON 备份不含账号，而同步快照和差异备份含账号校验资料；这些文件也不含 NAS 同步密钥。快照中的 local.ledger 是该次同步前的账本，必要时将它单独保存成 JSON 后通过原账本恢复入口载入；账号另由 NAS 同步。每次成功同步前会更新此本机快照，不代替长期备份。

## NAS 备份和恢复

每次写入前保留 shop.json.previous，并在 data/backups 保存最近 30 次写入前的历史版本。建议定期对整个 data 目录做 NAS 备份。

NAS 数据损坏或为空时，已建立关系的客户端会停止自动上传，不会自动覆盖。确认是新空目录且希望重建时，可在 App 手动立即同步并明确选择「以本机为准」。恢复时先停服务，备份整个 data，再将确认有效的 shop.json.previous 或 backups 中的版本复制为 shop.json，最后启动服务。客户端再次同步时，若本机也有修改会提示冲突。

单次同步数据上限 20MB，本机存储容量取决于 WebView/浏览器。封面较多导致本机快照无法保存时会停止此次同步并提示，不会丢弃当前账本。

## 外网与代理

HTTP 仅支持内网 IP 和本机测试地址，外网必须使用证书有效的 HTTPS。安卓使用受限制的原生网络桥接访问内网 HTTP；不会关闭 HTTPS 证书校验，也不会将同步密钥发送到重定向地址。

若配置反向代理，请给 POS 独立入口，转发到此项目的 3000/5689 端口；保留 Authorization、If-Match 和 ETag，允许 20MB 请求。已有示例经营账域名可增加新的代理路径，但需正确去掉该路径前缀；不能直接填原经营账的 /api/backup 服务地址。普通浏览器受到安全上下文、跨域和内网访问策略限制；HTTPS 页面应连接 HTTPS NAS 服务。

## 多店铺

管理员创建店铺并分配账号归属；商品资料共享，各店库存、销售、退款、出入库及支出分别保存。新店库存为 0。同一家店在设备间仍同步库存，店铺之间不会复制数量。本服务使用同步协议 v2，读取旧 v1 数据时将旧账本完整归入原店铺，旧客户端写入会被拒绝。

飞牛中更新源码后，应先停止 POS Compose 项目，再通过「更多 → 构建」启动。新版配置已包含 `pull_policy: build`，避免仍使用缓存的旧镜像。此行为参见 [Docker 官方文档](https://docs.docker.com/reference/compose-file/services/#pull_policy)。重建后健康接口的 syncVersion 应为 2。
