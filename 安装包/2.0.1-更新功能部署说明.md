# 2.0.1 启动检查更新

本包是现有 POS NAS 服务的增量更新包。先部署 NAS，再安装 2.0.1 APK。
不要删除原 data 文件夹、.env 或 docker-compose.yml，不要新建同步密钥。

## 本次安装

1. 将 `TCGshop-POS-NAS-update-v2.0.1.zip` 解压到原项目目录 `/vol1/1000/tcgshop-pos-sync`，合并目录并覆盖同名程序文件。解压后该目录内应能直接看到 `安装更新.sh` 和 `release/latest.json`，不能多套一层文件夹。
2. 在电脑 PowerShell 中连接 NAS：

   ```powershell
   ssh nasuser@192.0.2.10
   ```

3. 进入原项目并安装服务更新：

   ```sh
   cd /vol1/1000/tcgshop-pos-sync
   sudo sh ./安装更新.sh
   ```

   脚本只复制更新发布文件到 `data/updates` 并重建服务，不修改 `data/shop.json`。脚本会检查原项目及账本存在。

4. 验证外网入口：

   ```sh
   curl -fsS https://pos.example.com/tcgshop/api/update
   ```

   应返回 JSON，其中 `versionName` 为 `2.0.1`、`versionCode` 为 `26`，另有 `sha256`、`size` 等字段。该接口不需要同步密钥。若出现 401/404/503 或无法连接，先排查部署，不要安装新 APK。已有 `/tcgshop/` 反向代理能转发该路径，无需改动原账本入口。
5. 服务正常后，将 `TCGshop-POS-v2.0.1.apk` 发到手机／平板，覆盖安装。这是首次启用自动更新功能，需要手动安装一次。

## 使用规则

- 启动以及返回前台时，通过 Android 系统确认有互联网连接才发起更新检查。未联网直接进入，不请求更新服务。
- 联网检查通过后才加载账本或恢复自动同步。有新版本时必须下载并通过系统安装确认才能继续；不能点击空白或返回键关闭更新提示。
- 在线但服务异常：提示重试或退出，不误判为最新版本。离线后重新打开可离线使用。
- 管理员和店员均可在「数据与设置 → 当前版本」展开后点击「检查更新」。
- 安装包会校验大小、SHA-256、包名、版本和签名；仅接受同一 HTTPS 更新服务的下载，不跟随重定向。
- Android 需要允许本应用安装更新；首次会跳转到系统授权页。用户仍需在系统安装页面确认，普通 App 不能静默安装。
- 浏览器预览只展示手动入口，强制更新与安装由安卓原生层执行。

## 以后发布新版

新 APK 的 `versionCode` 必须递增，沿用原包名和签名。先构建，再在电脑项目根目录执行（替换实际新包路径）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tcgshop-android/publish-update.ps1 -Apk "安装包/新版本.apk" -Notes "本次更新内容"
```

脚本验证签名和版本并生成 `tcgshop-server/release`。把其中新生成的哈希命名 APK 先复制到 NAS 的 `data/updates`，然后上传 `latest.json` 为 `latest.json.tmp`，最后在 NAS 执行 `mv data/updates/latest.json.tmp data/updates/latest.json` 原子切换版本。以后仅发布新 APK 不需要重建 Docker。

版本文件仅提供公开 App 更新信息和下载；账本接口继续验证原同步密钥。不要把 .env 或账本放进公开更新目录。

## 验证范围

已做更新接口、下载内容、无效发布拒绝、路径限制、同步鉴权、双设备 NAS 同步及设置入口测试；APK 编译、签名与运行资源校验通过。尚未替你部署到真实 NAS，Android 系统安装授权与真机升级流程需在服务部署后验证。
